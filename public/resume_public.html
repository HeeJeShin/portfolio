소개

전시·행사 플랫폼을 4년간 개발·운영하고, 지자체 스마트관광 플랫폼(인제·용인)을 구축한 개발자입니다. JSP 레거시를 Next.js로 전환해 Lighthouse 성능 점수를 45에서 99로, LCP를 8.0초에서 0.8초로 개선했고, 모노레포·타입 선행 설계·Vitest 테스트(216개)로 어드민 프론트엔드를 설계하고 구축했습니다.

요청이 들어오면 "요청한 내용"보다 "요청하는 이유"에 집중합니다. 디자이너가 없는 프로젝트에서는 UI 가이드를 먼저 만들어 사업부서와 화면 기준을 합의했고, 결제 구조를 백엔드로 옮기는 개선도 근거를 정리해 설득했습니다. 현재는 사이드 프로젝트로 NestJS와 AI를 연동한 서비스를 만들며 백엔드까지 경험을 넓히고 있습니다.

AI를 활용하는 방식

2023년부터 AI를 업무에 써왔습니다. 처음엔 결과를 반신반의해서 오타 찾기처럼 작은 일부터 맡겼고, 검증할 방법을 갖춘 만큼씩 범위를 넓혀왔습니다. 기능을 빨리 만드는 것보다 무엇을 AI에 맡기고, 어떻게 확인할지를 먼저 정합니다.

  • AI가 만든 코드는 검증을 통과해야 반영합니다 — 개발자마다 검증 방식이 달라 같은 문제가 반복되는 걸 보고, 어드민 프로젝트에 CLAUDE.md로 컨벤션과 검증 규칙을 먼저 정했습니다. AI가 만든 코드는 타입 체크와 Vitest 테스트(216개)를 통과해야 반영되고, 결과는 CSV 리포트로 남아 누구나 확인할 수 있습니다.
  • 정답이 필요한 일은 코드와 데이터에, 해석과 안내는 AI에 맡깁니다 — AI는 그럴듯한 오답을 낼 수 있기 때문입니다. 행사장 수용인원 서비스(4J)에서는 AI가 도면에서 면적·출입구만 읽고 인원 계산은 코드가 하도록 나눴고, 중고차 가이드(중구)에서는 고질병 정보는 사람이 검증한 DB에서만 가져오고 AI는 "무엇부터 알아볼지" 안내에만 썼습니다.
  • 말보다 AI로 빠르게 만든 화면으로 합의합니다 — 비개발자와 기술 용어로 이야기하면 방향을 맞추는 데 시간이 오래 걸립니다. 디자이너가 없던 어드민에서는 AI로 UI 가이드 화면을 먼저 만들어 사업부서와 기준을 정했고, 임상간호연구(HomeCare)에서는 Claude Design으로 만든 프로토타입을 보여주며 의료진과 요구사항을 정리했습니다.
